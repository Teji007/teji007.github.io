Security first

Encryption is only part of the problem.

Vaurypt focuses on the parts users actually depend on: credential hardening, authenticated containers, key management, metadata protection, integrity checks and safe workflows.

⌘

◈

Authenticated containers

Encryption and integrity checks work together so wrong credentials and tampered containers fail cleanly.

▦

Protected metadata

Original filenames and archive metadata remain inside the encrypted container rather than sitting beside the ciphertext.

↻

Recovery-aware design

Recovery keys, keyfiles and multiple access slots provide alternatives to keeping one fragile password in one place.

!
No “uncrackable” claims.

Vaurypt is designed to make offline guessing difficult and to detect tampering. Security still depends on the implementation, strong credentials, configuration and the security of the machine handling plaintext.

Questions, answered

Security without the marketing fog.

Can a Vaurypt file be opened without the password?

Not through normal decryption. An attacker with the container can still attempt offline password guesses, so password quality and key-management practices matter.

Is Vaurypt “uncrackable”?

No. Vaurypt intentionally avoids absolute claims. It is designed around established cryptographic primitives, password hardening, authenticated containers and explicit threat-model limitations.

What happens if I forget the password?

There is no universal password-recovery mechanism. Recovery keys and keyfiles are optional ways to create additional access paths.

Can I protect folders, not just individual files?

Yes. Vaurypt can package and encrypt an entire folder while preserving its internal structure inside the encrypted container.

Does cloud storage see my original filenames?

The intended container workflow keeps original names and archive metadata inside the encrypted payload rather than exposing them as ordinary cloud-side files.

Is the source code open source?

No. Vaurypt is source-available/proprietary. Inspecting source for security review or learning is permitted under the project terms; reuse, modification, redistribution and integration require permission.
